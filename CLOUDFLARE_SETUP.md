# Revy's Bakes: Neon + Cloudflare Pages setup

The storefront remains hosted on Cloudflare Pages. Orders are stored in Neon Postgres, and payment receipts are stored in the private Neon Object Storage `assets` bucket.

## Local Neon setup completed

The Neon CLI was initialized and deployed against:

```text
Project: round-shape-60053607
Branch: production
Services: Postgres, Object Storage
```

`neon deploy` created `.env.local` with the database and Object Storage credentials. `.env.local` is ignored by Git and must never be committed.

The local verification command passed:

```text
Neon Postgres: connected, migrated, inserted, and read a verification order.
Neon Object Storage: uploaded and read a verification object.
Verification data cleaned up.
```

## Cloudflare Pages environment variables

In the Pages project, add these as encrypted **Production** variables:

```text
DATABASE_URL
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_ENDPOINT_URL_S3
AWS_REGION
OBJECT_STORAGE_BUCKET=assets
OWNER_API_TOKEN
PUBLIC_SITE_ORIGIN
```

Copy the first five values from the local `.env.local` file generated by Neon. Do not copy the secrets into source files. `PUBLIC_SITE_ORIGIN` should be the exact deployed origin, such as `https://revysbakes.pages.dev`.

The API reads these values inside `functions/api/orders.js`:

- `DATABASE_URL` connects through `@neondatabase/serverless`.
- The `AWS_*` values connect to Neon Object Storage through its S3-compatible endpoint.
- `OBJECT_STORAGE_BUCKET` selects the private `assets` bucket.
- `OWNER_API_TOKEN` protects the owner order list.

No D1 or Cloudflare R2 bindings are needed.

## Database schema

Run [`schema.sql`](./schema.sql) against the production Neon branch. The local verification script automatically applies it before its test, but production should be migrated intentionally before launch.

## Deploy

Connect the repository to Cloudflare Pages with:

```text
Framework preset: None
Build command: npm run build
Build output directory: /
Root directory: /
```

The Pages Function is deployed automatically from:

```text
functions/api/orders.js
```

The customer form posts multipart data to `/api/orders`. The function validates phone format, receipt type and size, recalculates the total from its server catalog, stores the receipt privately, and inserts the order.

## Owner dashboard

Open:

```text
https://your-domain.example/owner.html
```

The dashboard sends `Authorization: Bearer <OWNER_API_TOKEN>` to `/api/orders`. The token is held in memory only. Protect `/owner.html` with Cloudflare Access and allow only the owner's email address.

## Security requirements

- Keep `.env.local` out of Git.
- Keep the Neon Object Storage bucket private.
- Never put `DATABASE_URL`, S3 credentials, or `OWNER_API_TOKEN` in frontend files.
- Rotate the owner token if it is exposed.
- Use HTTPS and Cloudflare Access for the owner dashboard.
- Add a WAF/rate-limit rule for `POST /api/orders`.
